先看知识怎么进来。左边四类源：文件走 pypdf，我的简历十九块就是这么进来的；文章 URL 走 trafilatura 抓正文，我自己网站整站四十八页九百六十块；笔记和问答对走 CLI 和 web 双入口；第四类账号源，OAuth 云文档和动态流，现在只是注册桩还没接萃取，但方案已经过闸了——每个源右边那个标签就是它走哪套画像。为什么动态流不能跟前三类同参数：一条动态往往是「我最近在看什么」，它是当下状态不是长期事实。所以 feeds 画像四个参数全不一样，中间这行写着：每源只抽四条而不是八条，动态流噪声大要筛严；置信零点七；时效语义标 current，召回时按九十天半衰期衰减；而简历那类标 durable，只可被替换、不衰减。一句话，这条管线换的是参数不是分支。关键是中间这一步：不管哪类源进来，走的是同一条管线，没有 per-source 的特殊分支。管线里蒸两次——第一次切块加 embedding，进向量库；第二次是正文过四道闸萃取，四道闸分别是：没有源 chunk 出处直接不产出、prompt 只允许抽原文明确陈述的不推断不补全、一行一条每源最多八条防长文档爆断言、最后 tripwire 拿每条 claim 跟原文算余弦，低于零点二五说明抽出了原文没有的实体，当幻觉丢掉。右边是双产出，也是这页最想让你们记住的：同一批语料出两个知识面。chunk 面存原文原样，作答时供引用，citations 锚的就是它；断言面存结构化断言，四个桶各有来路——A 桶来自采集萃取，就是本页这条线；B 和 C 来自访谈折叠，下一页整页讲；D 来自反馈蒸馏，管腔调。底下三条：本页这条线是真跑的，c13 那块简历过一遍萃出六条 A_fact 断言，全带 refs 可以回原文核对，屏上这个 id 是真实运行输出。中间这条是 feeds 方案里我主动否决掉的两个设计，比参数值本身值钱：第一，主题槽用固定枚举——current_focus、current_employer、current_project 三个槽，我否决了让 LLM 自己产槽名，因为槽名一漂移，新断言就替换不掉旧的，整个替换机制直接失灵；第二，否决 valid_until 硬过期，因为设过期时间需要预知未来，我改用衰减加槽替换。背后是同一条判据：错误的合并比错过的合并伤害大——错合并会废掉一条还活着的真断言，而错过合并只是多留一条旧的。追问弹药：为什么不给每类源写专门的萃取分支——管线越少，防编造契约越好守，画像是一张可打印可审计的参数表，将来还能挂 autoevolve 自动调参；策略和机制分离是 ADR-0029 的主决策。第三条是诚实标注：存量九百八十八块不回填，每块过一遍 LLM 的钱不值得为沉睡语料花，只对新采集生效。这是有出处的事实怎么进来；下一个决策讲没出处的判断怎么挖出来。

讲完这场，可以带走的三个方法

Three transferable methods — beyond this project

评测先行Eval-first

机制：预留真答（被测者不可见）→ reference-based 盲测 → 相对阈值防凑分 → 小样本多采样。没有裁判，一切「优化」都只是感觉

评估闸开发Proposal → ADR → verify

机制：方案文档（含否决的备选）→ 人工评估闸 → ADR 记决策 → verify 真跑通才标完成。管住 agent 的不是 prompt，是闸门

砍刀定形Scope by cutting

机制：开工前把「不做什么」写进项目宪法（本项目三刀）；此后每个需求先对边界，撞线即拒

收口前送三个可以直接拿走的方法，都不限于这个项目。第一，评测先行：任何 AI 产品，先回答「怎么判定它变好了」再动手——刚才三个坑每一个都是评测系统先抓到的，这不是巧合，是因果。第二，评估闸开发：这个项目三十九个 ADR 背后是同一条流水线——方案先行、人工评估、机器验证，AI 写代码的时代人的价值在设闸门，这套方法我沉淀成了开源的 harness-kit。第三，砍刀定形：范围决策做在第一天比做在第一百天便宜一百倍。如果这三个方法里有任何一个对你们团队有用，这二十分钟就值了。最后一页收个尾。
